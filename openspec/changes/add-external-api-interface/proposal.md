## 为什么做这个变更

当前系统采用封闭的单体架构，仅支持网页界面访问，无法满足日益增长的业务拓展需求。随着合作伙伴对接意向的增多，我们需要提供标准化的接口，允许外部平台无缝集成游戏功能，同时保持数据实时同步。

**业务价值**：
- **快速拓展渠道**：合作伙伴可在自有平台直接嵌入游戏，无需重复开发，大幅降低接入成本
- **数据互通共赢**：实时数据同步使双方能够精准掌握用户行为和资金流水，提升运营效率
- **白标模式复制**：标准化接口为未来批量对接合作伙伴打下基础，实现业务规模化增长

**技术必要性**：
- 现有系统无对外接口能力，合作伙伴只能通过人工对账，效率低且易出错
- 缺乏标准化数据交换机制，无法支撑多平台协同运营
- 封闭架构限制了系统的扩展性和商业化潜力

**时机选择**：
- 已有2-3家合作伙伴明确对接需求，市场机会窗口期有限
- 现有系统架构相对稳定，具备改造基础
- 尽早建立接口生态，抢占市场先机

## 变更内容

**第一期（核心功能）**：
- 新增 RESTful API 接口层，提供核心数据查询功能
- 实现游戏窗口嵌入机制（iframe），支持跨域访问
- 提供简单的认证机制（API Key + 签名验证）
- 实现 Webhook 推送机制，通知关键事件（投注、中奖、充值、提款）
- 提供基础 API 文档（Markdown + Postman Collection）
- 基础安全措施（HTTPS、签名验证、速率限制、SQL 注入防护）

**后期优化（第二期）**：
- 更复杂的权限控制（Scope、IP 白名单）
- 批量操作接口
- 统计分析接口
- 多语言 SDK
- WebSocket 实时推送
- 监控和告警系统

## 功能模块

### 新增功能

**核心功能（必须实现）**：
- `api-authentication`: 外部系统 API 认证，基于 API Key + 签名验证的简单认证机制
- `game-window-embed`: 游戏窗口嵌入功能，提供简单的 iframe 嵌入方式
- `game-data-sync`: 游戏数据查询接口，提供投注记录、流水、开奖结果的查询功能（只读）
- `user-data-api`: 用户数据查询接口，提供用户信息、账户余额的基础查询功能（只读）
- `transaction-webhook`: 交易事件 Webhook，在关键事件时主动通知外部系统（简单重试机制）
- `api-documentation`: 基础 API 文档，提供 Markdown 文档和 Postman Collection

### 修改的现有功能
- 无现有功能需求变更（仅新增接口层，不改变现有网页界面功能）

## 影响范围

**受影响的代码模块**：
- `web/hide/login.php` - 需要扩展以支持 API Token 认证
- `web/hide/play.php` - 游戏逻辑需要支持 API 调用
- `web/hide/bao.php`, `web/hide/record.php` - 投注和记录查询需要 API 接口封装
- `web/hide/money.php` - 资金数据需要通过 API 暴露
- `web/hide/kj.php` - 开奖数据需要 API 访问支持

**新增的代码模块**：
- `web/api/` - 新建 API 控制器目录
- `web/class/ApiAuth.php` - API 认证类
- `web/class/ApiResponse.php` - API 响应格式化类
- `web/class/WebhookManager.php` - Webhook 管理类
- `web/embed/` - 游戏窗口嵌入页面目录

**数据库影响**：
- 新增 `api_keys` 表 - 存储外部系统的 API Key 和 Secret（InnoDB 引擎）
- 新增 `api_logs` 表 - 记录 API 访问日志（InnoDB 引擎）
- 新增 `webhooks` 表 - 存储 Webhook 配置（InnoDB 引擎）
- 新增 `webhook_logs` 表 - 记录 Webhook 调用日志（InnoDB 引擎）
- 现有表暂不修改，降低改造风险

**安全考虑（MVP 阶段必须做）**：
- 所有 API 查询使用 PDO 预处理语句，防止 SQL 注入
- 移除现有代码中的已知后门
- API Key + 签名验证，防止未授权访问和参数篡改
- 强制 HTTPS 加密传输
- 简单的速率限制（每个 API Key 每分钟最多 100 次请求）
- 基础输入验证（白名单验证必填参数）

**安全考虑（后期优化）**：
- IP 白名单
- 更细粒度的权限控制（Scope）
- 详细的操作审计日志
- WAF（Web 应用防火墙）

**部署影响**：
- 需要配置 HTTPS 证书（必须）
- 需要安装 Redis（用于速率限制）
- 需要确保 PHP 支持 PDO 扩展
- 可能需要调整服务器防火墙规则
